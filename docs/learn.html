45 MIN · START HERE

Serving map: request đi qua đâu?

Bắt đầu từ toàn pipeline. Client gửi prompt → HTTP server → tokenizer → queue → scheduler → prefill → decode loop → detokenizer → streaming response. Mọi metric phía sau chỉ là timestamp hoặc rate trên đoạn đường này.

Token

Đơn vị rời rạc mà model đọc và sinh; không đồng nhất với từ hay ký tự.

Frontend

HTTP, validation, tokenize/detokenize và streaming—thường chạy trên CPU.

Engine

Scheduler, cache manager và model executor phối hợp GPU work.

Critical path

Chuỗi công việc quyết định wall-clock latency; phần song song ngoài chuỗi không cộng thẳng.

Gate: Vẽ được sequence diagram từ submit đến last token và chỉ ra CPU/GPU boundary.
01
60 MIN · MEASUREMENT LANGUAGE

Metrics: TTFT, TPOT và throughput

Không tối ưu một từ viết tắt trước khi định nghĩa chính xác hai timestamp tạo ra nó. Luôn hỏi unit, aggregation, warm-up, percentile và client/server clock.

TTFT

Time To First Token: submit → token đầu. Gồm queue, tokenize, prefill và first decode.

TPOT

Time Per Output Token: thường là (last−first)/(N−1). Phải xác nhận evaluator.

ITL

Inter-Token Latency: khoảng cách giữa từng token; cho thấy jitter mà mean TPOT che mất.

Throughput

Tokens hoặc requests mỗi giây của cả hệ thống; có thể tăng trong khi latency một user xấu đi.

Poisson arrival

Inter-arrival time theo exponential distribution; tạo burst/queue tự nhiên dù rate trung bình cố định.

Percentile

p95/p99 mô tả tail. Mean không đủ cho workload có queueing và batch interference.

Gate: Tự tính TTFT/TPOT từ raw timestamps và giải thích vì sao 47/4 cho 63.19 ERS.
02
2–3 HOURS · MODEL EXECUTION

LLM inference: prefill, decode và state

Prefill xử lý nhiều prompt tokens song song; decode sinh một token mỗi sequence mỗi step. Hai phase có shapes và bottleneck khác nhau. LFM2.5 còn là hybrid: 10 convolution blocks và 6 GQA attention blocks.

Prefill

Đưa toàn prompt qua model, thường compute-heavy và ảnh hưởng TTFT.

Decode

Autoregressive loop; batch nhiều sequences để amortize weight reads và launch work.

Attention

Q truy vấn K/V của lịch sử; chi phí state tăng theo context length.

GQA

Grouped-Query Attention: nhiều query heads chia sẻ ít KV heads để giảm cache bytes.

KV cache

Lưu Key/Value cũ để decode không tính lại toàn prefix; capacity quyết định concurrent tokens.

ShortConv state

Recurrent convolution state của hybrid layers; semantics rollback khác attention KV.

Gate: Tính được weight bytes và KV bytes/token từ model config; phân biệt state của attention với convolution.
03
3 HOURS · PHYSICAL LIMITS

GPU hardware: SM, memory và roofline

GPU không chỉ là “TFLOPS”. Kernel bị giới hạn bởi compute, memory bandwidth, latency, occupancy hoặc launch overhead tùy shape. RTX 4080 SM89 và H200 SM90 MIG có câu trả lời khác nhau.

SM

Streaming Multiprocessor: đơn vị thực thi chứa warps, registers, shared memory và schedulers.

Warp

Nhóm 32 threads thực thi cùng instruction; divergence làm lãng phí lanes.

Registers

Storage nhanh theo thread; dùng quá nhiều làm giảm active warps/occupancy.

HBM / GDDR

Global GPU memory. HBM có bandwidth/behavior khác GDDR6X của RTX 4080.

Arithmetic intensity

FLOPs trên mỗi byte memory traffic; cầu nối giữa algorithm và roofline.

MIG

Hardware partition của datacenter GPU, chia SM/L2/memory resources và tạo target riêng.

Gate: Không gọi FLOP/peak-FLOPS là measured compute time; nêu được counter cần đo để kiểm chứng.
04
3–4 HOURS · CUDA MENTAL MODEL

CUDA execution: kernels, streams và graphs

CPU enqueue GPU work; GPU thực thi bất đồng bộ. Một kernel launch không mặc nhiên là CPU↔GPU round-trip, và synchronization mới buộc host chờ. CUDA Graph gom sẵn chuỗi operations để giảm launch/scheduling overhead.

Kernel launch

Host enqueue grid lên stream. Chi phí host tồn tại, nhưng không đồng nghĩa chờ kernel xong.

Grid / block

Cách threads được nhóm và map lên SM; shape ảnh hưởng utilization và memory access.

Stream

Ordered command queue. Nhiều streams có thể overlap nếu dependency/resources cho phép.

Synchronization

Event/API làm host hoặc stream phải chờ; thường tạo gap rõ trên timeline.

CUDA Graph

Capture/replay execution graph để giảm Python/driver launch work cho shapes ổn định.

Graph break

Dynamic control/operator làm compiled/captured region bị chia, trả overhead về eager path.

Gate: Nhìn timeline và phân biệt host gap, kernel duration, synchronization và graph replay.
05
HALF DAY · EVIDENCE TOOLS

Nsight: Systems trước, Compute sau

Nsight Systems trả lời “thời gian đi đâu?” trên toàn timeline. Nsight Compute trả lời “kernel này bị giới hạn bởi gì?” bằng hardware counters. Dùng đúng thứ tự để không profile chi tiết một kernel ngoài critical path.

Nsight Systems

CPU threads, CUDA API, streams, kernels, NVTX và synchronization theo wall-clock.

Nsight Compute

Kernel-level counters: occupancy, memory throughput, instructions và stalls.

NVTX

Named ranges gắn semantic phase như prefill/decode vào low-level timeline.

Achieved bandwidth

Bytes/s thật của kernel, khác bandwidth lý thuyết của GPU.

  • Profile representative warm replay, không profile mọi request.
  • Giữ profiler overhead ngoài score run.
  • Bucket theo batch size và prefill/decode phase.
Gate: Từ Systems chọn được đúng kernel/gap; từ Compute đưa ra một hypothesis có counter hỗ trợ.
06
1 DAY · SERVING ENGINE

vLLM internals: batching, pages và scheduler

vLLM tăng throughput bằng continuous batching và quản lý cache theo blocks/pages. Đọc source theo request lifecycle thay vì theo folder: frontend → scheduler → KV manager → model runner → output processing.

Continuous batching

Requests vào/ra batch ở mỗi iteration; không chờ cả static batch hoàn tất.

PagedAttention

KV cache chia blocks để giảm fragmentation và cho phép allocation linh hoạt.

Scheduler budget

Giới hạn sequences/tokens mỗi step; cân bằng TTFT của arrivals với TPOT của decodes.

Chunked prefill

Chia prompt dài thành chunks để tránh một prefill độc chiếm iteration.

Prefix caching

Tái dùng computed prefix blocks; lợi ích phụ thuộc exact token prefix và eviction.

Hybrid KV manager

Quản lý attention KV và recurrent state specs khác nhau trong cùng model.

Gate: Với một request, chỉ ra nơi queueing, block allocation, prefill scheduling và decode scheduling diễn ra.
07
HALF DAY · NUMERICS

Precision: BF16, FP8 và quantization

Quantization đổi storage, bandwidth và compute path nhưng cũng thêm scale/dequant operations và numerical risk. “Ít VRAM hơn” không tự động đồng nghĩa “latency thấp hơn”.

BF16

16-bit floating format với exponent rộng; baseline phổ biến cho inference.

FP8

8-bit floating formats như E4M3/E5M2; cần scale và hardware/kernel support.

W8A8

Weights và activations 8-bit; performance phụ thuộc fused GEMM path thật sự được chọn.

KV FP8

Giảm khoảng một nửa attention cache bytes; capacity thường là lợi ích đầu tiên.

Scale calibration

Chọn scale từ data để giảm clipping/underflow thay vì dùng mặc định mù quáng.

Quality gate

Exact greedy tokens hoặc task metric/tolerance xác định optimization còn hợp lệ.

Gate: A/B weights FP8 và KV FP8 riêng; báo memory, latency và quality như ba outcomes độc lập.
08
1–2 DAYS · KERNEL ENGINEERING

Triton và fusion: chỉ sau profiler

Fusion giảm launch count hoặc memory round-trips bằng cách giữ intermediate on-chip. Nhưng kernel lớn hơn có thể tăng registers, giảm occupancy và thua kernel rời—đặc biệt khi CUDA Graph đã giảm host overhead.

Triton program

SPMD program instance xử lý một tile; compiler map operations xuống GPU code.

Fusion

Kết hợp operators để tránh intermediate HBM traffic hoặc launches.

On-chip

Registers/shared memory gần SM; nhanh nhưng capacity hữu hạn.

Autotune

Benchmark candidate configs cho shapes/hardware cụ thể; không phải universal answer.

Fallback

Original correct path dùng khi dtype, shape, mode hoặc architecture không phù hợp.

Property test

So reference trên nhiều shapes/dtypes/edge values, không chỉ một golden case.

Gate: Kernel thắng correctness matrix, shape matrix và end-to-end A/B trên đúng SM target.
09
ONGOING · SCIENTIFIC CONTROL

Experiment method: biến submission thành thông tin

Pin artifact, đổi một biến, randomize A/B order, ghi raw data và định nghĩa kill criterion trước khi chạy. Một integration bundle có thể là release candidate nhưng không thể chứng minh từng optimization.

Baseline

Artifact/config reference có thể tái lập, không chỉ một con số trong notebook.

Noise floor

Mức variation tự nhiên; gain nhỏ hơn mức này chưa có ý nghĩa thực nghiệm.

A/B/A

Quay lại baseline sau candidate để phát hiện drift theo thời gian.

Provenance

Image digest, git SHA, model revision, env và source hashes đi cùng mọi result.

Kill criterion

Điều kiện dừng viết trước, giúp không tiếp tục hướng đắt vì sunk cost.

External validity

Candidate local thắng có còn thắng trên H200 MIG/evaluator thật hay không.

Gate: Mỗi row ledger trả lời một câu hỏi và có parent, one_change, evidence, outcome.

QUICK REFERENCE

Glossary: các thuật ngữ còn lại

HBM

High Bandwidth Memory, bộ nhớ package-side trên datacenter GPUs.

Tensor Core

Hardware matrix operations cho mixed precision như BF16/FP8.

Occupancy

Tỷ lệ warps active so với maximum; là diagnostic, không phải mục tiêu tuyệt đối.

Memory-bound

Performance giới hạn bởi data movement hơn arithmetic throughput.

Compute-bound

Arithmetic units là giới hạn chính; tăng bandwidth không giúp nhiều.

Kernel backend

Implementation được dispatch như FlashAttention, Triton hay custom CUDA.

Speculative decoding

Draft nhiều tokens rồi target verify; lợi ích phụ thuộc accepted work/cost.

Acceptance rate

Tỷ lệ draft tokens được nhận; không đủ một mình để xác định break-even.

Docker overlay

Ghi đè source lên package trong image; nhanh nhưng cần digest/ABI guards.

tcmalloc

Alternative allocator; chỉ dùng khi CPU allocation profiling/A-B hỗ trợ.

SM89 / SM90

Compute architectures Ada/Hopper; khác resources và optimal kernel configs.

Graph capture size

Batch/shape được capture; mismatch có thể quay về eager hoặc graph khác.
